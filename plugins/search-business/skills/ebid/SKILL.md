# ebid — 도로공사 공고·계약 검색·개찰·첨부

## 언제 쓰나
공고를 찾거나, 체결된 계약을 찾거나, 특정 공고의 결과를 묻거나, 첨부를 받아 내용을 확인해야 할 때.
자동화되는 소스는 **ebid 하나뿐이다.** 사용자가 다른 기관·시스템(나라장터·조달청·IRIS·국방전자조달 등)을 지목하면 **되묻지 말고 한 줄로 밝힌다** — "이 도구는 한국도로공사 ebid 만 검색합니다. ebid 기준으로 찾아드릴까요?" 그 시스템을 모르면 아는 척하지 말고 모른다고 쓴다. 소스별 가능 여부는 `references/소스-접근성.md`.

## 표준 흐름
검색(공고 또는 계약) → (필요 시) 상세·개찰 → 첨부 목록 → 다운로드 → 판독. 각 단계는 아래 도구 하나씩.

## 도구 — 스킬 폴더 기준 경로, 어느 작업 폴더에서든 실행
```bash
python scripts/ebid_search_common.py   --keyword "구내통신" --md                    # 입찰공고 검색 (공사·용역·물품)
python scripts/ebid_search_contract.py --keyword "터널" --from 20240101 --md        # 계약공개현황 검색
python scripts/ebid_search_contract.py --keyword "VMS" --detail --md              # 계약 + 건별 상세(담당자·업체·수의근거)
python scripts/ebid_search_common.py   --from 20260815 --md                       # 키워드 없이 최근 공고 전체 (--from 필수)
python scripts/ebid_search_common.py   --keyword "감리" --type 용역 --md          # 유형이 명백하거나 사용자가 지정한 경우에만 --type
python scripts/ebid_result.py --notice 202602664 --table                          # 공고 상세·개찰결과
python scripts/ebid_fetch.py  --notice 202602663 --list                           # 첨부 목록 (파일 안 만듦)
python scripts/ebid_fetch.py  --notice 202602663 --only 단가                    # 기본 ./ebid-out/ 밑에 받음
python scripts/ebid_fetch.py  --notice 202605940 202605691 --out-dir ./자료   # 공고 여러 건 배치
```
- stdout 은 JSON. `--md` 는 대화창에 그대로 붙일 마크다운 표, `--table` 은 터미널용 한 줄 표. 진단은 stderr.
- 종료코드: 0 성공 · 1 통신 실패 · 2 인자 오류/공고 미발견 · 3 첨부·상세 **일부** 실패(성공분은 출력됨). 실패 건은 결과 JSON 의 `실패`(첨부) / `상세오류`(계약) 에 **종류 코드**(network·http·server·file)와 메시지로 남는다 — 답변에 실패 건과 종류를 그대로 적는다. `network` 면 사용자 환경(프록시·Codex 샌드박스) 문제라 재시도보다 환경 안내가 먼저.

## 공고 검색과 계약 검색은 다른 도구다
- **입찰공고** (`ebid_search_common.py`): 공고 시점 기준. 경쟁입찰만 있다. 공고일 기간, 공고명 검색, 건별 딥링크 있음.
- **계약공개현황** (`ebid_search_contract.py`): 체결 시점 기준. **수의계약·지명경쟁 포함** 전체 체결 원장. 체결일 기간, 계약명 검색, 건별 딥링크 없음.
- 질문이 "공고가 났나/나올까" 면 공고만, "누가 했나/얼마에 계약됐나/수의로 됐나" 면 계약만 돌린다. 둘 다 필요할 때만 둘 다.
- 공고 검색에서 계약 필드를 언급하지 않는다. 계약 검색에서 공고 상태(공고중·낙찰 등)를 추정하지 않는다.

## 검색 규칙 (공통)
- `--type` 은 기본적으로 **주지 않는다** — 두 도구 모두 생략 시 전체 유형을 한 번에(병렬) 검색하며 속도 차이가 거의 없다. 붙이는 경우는 둘뿐: (a) 사용자가 "용역만", "물품 공고" 처럼 유형을 지정했을 때, (b) 질문에서 유형이 명백할 때("감리용역" → 용역, "지급자재 구매" → 물품). 애매하면 전체로 검색하고, 결과 표가 유형별로 나뉘니 그대로 보여준다.
- **키워드 없이 검색**("요즘 뭐 나왔어", "최근 계약 전부")할 때는 `--keyword` 를 생략하고 **`--from` 을 반드시 준다(없으면 종료코드 2로 거부, `--to` 는 생략 시 오늘)** — 스크립트는 건수를 제한하지 않으므로 기간으로 조절한다. 기준: 2주~1개월(계약 1개월 ≈ 350건, 공고 3유형 1개월 ≈ 130건). `--type` 은 위 규칙과 같다(기본 생략). 답변에는 적용한 기간을 밝힌다.
- 기간 미지정 = 최근 1년. 적용한 기간은 건수 줄에 그대로 쓰고 **별도 문장으로 안내하지 않는다** — 같은 정보를 두 번 쓰는 만큼 답변이 늦게 뜬다.
- 과거 이력·지난 사업을 묻는 질문이면 되묻지 말고 질문에 맞는 범위로 `--from` 을 지정하고, 적용한 범위를 답변에 쓴다.
- 두 지명이 합쳐진 노선명("함양울산")은 지명별("함양", "울산")로 따로 검색해 교차 확인한다 — 연속 문자열 부분일치라 표기 변형을 놓친다.
- 공고번호로 조회할 때는 기간 개념이 없다.
- 공고번호는 9자리(예 202603454). 계약 레코드의 **계약번호는 11자리 = 공고번호 + 2자리**(앞자리: 묶음 공고 안의 세부 건 순번, 뒷자리: 1). 묶음 공고 1건이 계약 여러 건으로 갈라지므로 계약 표에 같은 공고번호가 반복되는 건 정상. "계약번호가 왜 공고번호랑 달라?" 에는 이걸 답한다.

## 계약 상세(`--detail`) 규칙
- 건당 요청 1회가 추가된다. 기본 상한 30건(체결일 최신순) — 초과 시 stderr 경고가 나오니 답변에 "상위 30건만 상세" 를 밝히고, 필요하면 기간을 좁히거나 `--detail-limit` 을 올린다.
- 상세가 주는 것: 계약기간·발주처·담당자와 부서 전화·계약업체 대표자/주소/지분율(공동도급이면 여러 행)·수의계약 근거 조문+사유·설계금액/예정가격/개찰일시/낙찰방법. 전자수의 건도 설계금액·예정가격이 있다(전자 견적을 거침).
- 설계금액·예정가격이 비어 있으면 희망수량 등 입찰 정보가 없는 건이다. "정보 없음" 이 아니라 "입찰 정보가 없는 계약 유형" 으로 쓴다.
- 담당자·대표자 연락처는 사이트가 공개한 값 그대로다. 요청받은 범위 밖으로 모아서 목록화하지 않는다.

## 대화 출력 — 건수 한 줄 + 결과 파일 링크 한 줄
검색이든 첨부든 답변의 뼈대는 같다. **링크는 결과 파일 한 줄뿐이다** — 저장 폴더나 개별 파일마다 링크를 달지 않는다(40개면 답변이 링크로 뒤덮이고, 폴더는 파일 링크에서 한 단계 위일 뿐이다). 이모지를 쓰지 않는다.
```
결과 파일: [ebid\_공고\_VMS\_20260831-1530.md](file:///C:/Users/me/AppData/Local/Temp/claude/…/scratchpad/ebid_공고_VMS_20260831-1530.md)
```
- **링크 문법은 실측으로 정해져 있다**(터미널·앱 양쪽 확인). URL 은 **절대경로**(Windows `\`→`/`, 상대경로면 `file:///ebid-out/…` 로 둔갑해 안 열린다)를 쓰되 **`<...>` 로 감싸지 않고**(감싸면 앱이 못 연다) **공백을 `%20`, 괄호를 `%28`·`%29` 로 인코딩**하며(공백을 두면 터미널에서 아예 링크가 안 되고, 짝 안 맞는 `(` 가 있으면 경로가 틀어진다) **라벨의 `[`·`]`·`_` 에 이스케이프 규칙 추가**한다(`\[`·`\]`·`\_`, 백슬래시는 화면에 안 보인다). `_` 이스케이프가 특히 중요하다 — 안 하면 Claude Code 터미널이 라벨 안 언더스코어를 기울임 시도로 오인해 링크 문법 자체가 깨지고 URL 원문이 그대로 노출된다(실측, 백틱으로 감싸는 건 효과 없음). 한글·URL 안의 대괄호는 그대로 둔다. 스크립트는 `_ebid.normalize.md_file_link()` 가 다섯 다 처리한다. 라벨 형식은 고정하지 않는다.
- 파일을 채팅창에 첨부 카드로 붙이는 도구는 이 환경에 **없다.** 링크가 전부이고, 안 열리는 터미널이면 `! start "" "<경로>"`(Windows) / `! open` / `! xdg-open` 을 안내한다.

### 검색 결과 — 건수 한 줄 + 링크. 표는 요청받을 때만
표는 행 수에 비례해 오래 걸린다(34행 ≈ 100초). 그래서 기본 출력은 표가 아니라 링크다(약 30토큰, 몇 초).
1. **검색 도구 1회** — `--type` 생략(3유형 병렬, 2초대). `--md --out` 으로 md 한 파일만 저장하고 stdout 에는 **건수만** 찍는다. 유형별로 쪼개 검색하지 않는다 — 왕복만 늘고 먼저 뜨는 건 그 유형뿐이다.
2. **짧은 텍스트 블록 하나로 끝낸다.** `VMS 공고 34건 — 공사 21 · 물품 13 (2026-03-01~2026-08-31)` 한 줄 + 위 링크 한 줄. **건수 한 줄과 결과 파일 링크 한 줄이 전부다.** 검색조건 해설·기간 안내·요약·표 제안·다음 단계 안내를 덧붙이지 않는다 — 덧붙이는 만큼 늦게 뜬다.
3. **표는 사용자가 표를 달라고 했을 때만 낸다. 먼저 제안하지 않는다** — "표로 보시겠습니까" 같은 줄을 붙이지 않는다. 요청받았고 100행이 넘으면 그때만 소요(행당 약 3초)를 알리고 확인받는다. 임의의 건수 상한으로 거절하지 않는다 — 사용자가 알고 요청한 것이다.
- 표를 낼 때도 직접 다시 만들지 않는다. `--md` 가 만든 표를 그대로 보여주고 검색 조건 한 줄만 붙인다. 요약·해석은 물을 때만.
- 공고: 발주유형별 표 3개 `### [공사] '키워드' 검색 결과 (기간, n건)`. 열 = 공고번호 · 지역 · 공고명(딥링크) · 설계금액 · 계약방법 · 공고일 · 상태.
- 계약: 단일 표 `### [계약] …`. 열 = 구분 · 공고번호 · 계약명 · 계약방법 · 사업자번호 · 계약업체 · 총계약금액 · 체결일. `--detail` 이면 사업자번호 대신 대표자·예정가격·계약기간·발주처·담당자·수의근거 열이 붙는다.
- 계약은 건별 링크가 없다. 조회 화면 `https://ebid.ex.co.kr/default.do?menuId=NPRO20001` 과 검색 조건(계약명·체결일 범위)을 안내한다.
- 취소공고·재공고 원공고도 표에서 빼지 않는다(상태 열로 구분). 금액은 원 단위 천 단위 콤마, 억 환산은 요청 시에만.

### 첨부 다운로드 결과
`다운로드 결과`(`_받은목록.md`) 링크 한 줄 뒤에, 공고마다 제목 한 줄과 표 하나. 폴더 링크는 매니페스트 안에 있으니 답변에 또 쓰지 않는다.
```
202605940_[긴급]2026년 광주전남본부 CCTV 및 VMS 통합설치공사

| 파일 | 크기 | 상태 |
|---|---:|---|
| 공사입찰공고문.hwp | 260,608B | 성공 |
| 단가산출서.xlsx | 5,616,582B | 스킵 (이미 받음) |
| 시방서.hwpx | 4,446,265B | 실패 (server) |
```
- 상태는 **성공 / 스킵 / 실패** 셋. 실패는 괄호에 종류 코드(network·http·server·file)만 짧게 — 자세한 사유는 `_받은목록.md` 에 있으니 답변에 길게 적지 않는다.
- 실패가 있으면 첫 줄에 `n개 중 m개 실패` 를 밝힌다.

## 결과를 어디에 저장하나 — 경로는 고정하지 않는다
검색 결과는 항상 md 한 파일로 저장한다. **어디에 두는지는 못 박지 않는다** — 환경마다 "버려도 되는 파일을 두는 곳" 이 다르고 사용자 선호도 다르다.
1. **그 에이전트가 임시·세션 파일을 두는 곳**을 쓴다. Claude Code = 세션 스크래치패드(경로는 시스템 프롬프트가 매 세션 알려준다. 세션 종료·임시폴더 정리로 사라지니 **임시 확인용만**). Codex = 스크래치패드가 없으니 워크스페이스 안 `./ebid-out/`(`workspace-write` 는 밖을 막고 `.codex/`·`.git/` 은 안에서도 쓰기 금지). 그 밖 = 그 환경의 안내를 따르고, 없으면 워크스페이스 안.
2. **사용자가 위치를 지정하면 그 선택을 에이전트 메모리에 적어두고** 다음부터 꺼내 쓴다(메모리를 지원하는 에이전트라면). 환경이 매 세션 알려주는 기본 경로는 기억할 필요가 없다 — 기억할 값은 시스템이 이미 주는 것이 아니라 **사용자의 선택**이다. 바뀌면 갱신한다.
3. **보관 요청**("저장해줘 / 남겨줘")은 임시 폴더가 아니라 **워크스페이스 안 `./ebid-out/`** 에 쓴다. 저장 전에 경로·파일명을 한 줄로 알리고, 같은 키워드의 이전 파일이 있으면 함께 알린다(기본은 덮어쓰지 않고 새로 남김).
4. **스크립트는 절대경로로 호출하고 `cd` 로 스킬 폴더에 들어가지 않는다** — 결과가 플러그인 캐시에 쌓이면 업데이트·재설치 때 사라지고 사용자가 자기 프로젝트에서 찾지 못한다.
- `ebid-out/` 하위 폴더는 워크스페이스에 쓸 때만 만든다. 스크래치패드는 이미 세션별로 격리돼 있어 바로 둔다.

### 이름 규칙 — 만드는 이름에 괄호를 쓰지 않는다
- 검색 결과 `ebid_<공고|계약>_<키워드>_<YYYYMMDD-HHMM>.md` (예 `ebid_공고_VMS_20260831-1530.md`)
- 첨부 폴더 `<공고번호>_<공고명>/` (예 `202605940_[긴급]2026년 광주전남본부 CCTV…`) · 첨부 파일은 서버가 준 원본명 그대로(스크립트가 금지문자·100자 정화) · 받은 목록은 `--out-dir` 바로 밑 `_받은목록.md`
- **접두사에 괄호를 쓰지 않는다.** 링크 URL 은 `](...)` 안에 들어가서 경로의 괄호를 매번 `%28`·`%29` 로 인코딩해야 한다 — 우리가 만드는 이름에 굳이 넣을 이유가 없다(공고명 자체에 든 괄호는 스크립트가 처리한다).
- 키워드의 공백·특수문자는 `_` 로, 키워드 없이 검색했으면 `전체`. 같은 분에 두 번이면 초까지(`-153042`). **덮어쓰지 않는다** — 같은 키워드라도 기간·유형이 다르면 비교해야 한다. 검색 조건은 이름에 넣지 않는다(md 첫 줄에 이미 있다).

## 응답 규칙
- 발주유형 약어를 쓰지 않는다 → 공사 공고 / 용역 공고 / 물품 공고.
- 공고는 항상 **공고번호 + 공고명 전체**로 부른다.
- 딥링크는 결과 JSON 의 `딥링크` 값을 **전체 URL 그대로** 안내한다. 중간을 `...` 로 줄이면 식별자가 깨져 목록 화면으로 떨어진다. 비어 있으면 "ebid.ex.co.kr → 전자조달 → 입찰공고 → 공고번호 검색" 을 안내한다.

## 첨부·판독 규칙
- 목록은 `--list`(파일 안 만듦), 다운로드는 `--out-dir`(폴더). 검색 CLI 의 `--out` 은 **파일 경로**라 이름이 다르다 — 바꿔 넘기면 그 이름의 폴더가 조용히 생긴다.
- **첨부는 임시 폴더에 받지 않는다.** 항상 워크스페이스 안(기본 `./ebid-out/`)에 받는다 — 세션이 끝나 사라지면 다시 받는 비용이 크고(10공고 ≈ 211MB), 사용자가 문서 스킬로 열어봐야 한다. 그 밑에 공고별 폴더와 `_받은목록.md` 가 생긴다(이름은 「이름 규칙」).
- **공고 여러 건은 한 번에 준다** — `--notice A B C`. 세션 1회 + 병렬로 처리한다(실측 10공고 40파일 211MB: 공고별 반복 호출 177초 → 배치 28초). 공고마다 따로 호출하지 않는다.
- 받기 전에 `--list` 로 **합계 용량을 확인해 사용자에게 알린다.** 100MB 를 넘으면 받을지 먼저 묻는다. **부분 실패(종료코드 3)면 같은 명령에 `--skip-existing` 을 붙여 다시 돌린다** — 폴더·파일명·크기가 맞는 것은 건너뛰고 실패분만 받는다. 공고를 통째로 다시 받지 않는다.
- hwp/hwpx/pdf/xlsx 는 문서 스킬(kordoc 등)로 변환한 뒤 읽는다. 변환 도구가 없으면 다운로드까지만 하고 설치를 안내한다.
- 검색·스크립트는 후보를 찾는 데까지다. "없다"는 판정은 원문을 직접 읽은 뒤에만 내린다 → `references/문서-판독-지침.md`.

## 이 스킬이 하지 않는 것
결과 저장소·대장·예측 판정은 호출하는 프로젝트의 몫이다. 필요하면 JSON 을 파일로 받아 프로젝트 쪽에서 가공한다.
